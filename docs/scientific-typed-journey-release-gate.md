# Typed journey release gate

The typed journey is a candidate capability. A successful desktop History record or HTTP broker job alone does not promote support. `tools/scientific-broker/typed_journey_release.py` accepts one six-capability release, one managed desktop journey, and one broker journey. It seals a local coexistence record only when all three have the same source commit and MATH3D consumer, and the journeys derive from the same saved Boolean run.

Run `python tools/scientific-broker/typed_journey_release.py build --release RELEASE.json --desktop DESKTOP/results.json --broker BROKER/broker-result.json --broker-config PROFILE.json --output journey-release.json`. Run the same command with `verify --record journey-release.json` after publication. The verifier checks the release seal and current six-capability support, source snapshots, full desktop and broker artifact inventories and content hashes, independent product document relations, and the broker's pinned profile. It rejects a historical six-capability release before the costly support recheck.

The release record is a local candidate seal. Final publication still requires a clean installed DevShell run at the merged source HEAD, pulled MATH3D consumer identity, six-capability requalification at that HEAD, desktop and broker journey evidence from one saved Boolean parent, a signed portable bundle carrying the records and artifacts, and independent offline verification.
