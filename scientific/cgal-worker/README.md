# Standalone CGAL mesh workers

`devshell_cgal_worker` remains the existing validation/remeshing executable. `devshell_cgal_query` is a separate bounded point-to-triangle-mesh AABB query tool. It accepts a triangle OBJ and three finite coordinates within ±1,000,000, rejects degenerate and nonmanifold input, and writes a new `results.json` in its working directory. Distance is unsigned distance to the surface; it does not classify inside versus outside.

`devshell_cgal_orientation` separately inspects a triangle mesh or writes an outward-oriented copy of one closed connected volume. It refuses degenerate, self-intersecting, nonmanifold, disconnected and open repair inputs. Inspection of an open mesh reports `undetermined`. It writes `results.json` in a fresh working directory and never overwrites an existing output OBJ. The repair changes face winding only; it does not fill holes or repair geometry.

`devshell_cgal_hole_repair` is a separate native executable with explicit `fill-one-hole` (three-edge boundary) and `fill-quad-hole` (four-edge boundary) operations. Each accepts one connected triangular manifold with exactly one boundary loop, rejects degenerate or self-intersecting input, and writes an OBJ only after the expected one or two patch triangles close an outward volume. A flat open square does not pass the volume check. Neither operation performs general mesh repair.

Build with the installed CGAL CMake package, for example `cmake -S scientific/cgal-worker -B <build-dir> -DCGAL_DIR=<CGAL-prefix>/Library/lib/cmake/CGAL` followed by `cmake --build <build-dir> --config Release --target devshell_cgal_query`. Run the query in a fresh directory with the CGAL Conda prefix and `Library/bin` on `PATH`.

The same CMake project builds `devshell_cgal_hole_repair` as a separate target. `python tools/scientific_cgal_repair_fixture.py verify` checks the authored one-hole tetrahedron and its CC0 manifest without changing the original four-fixture corpus. `scientific_cgal_hole_repair.py run --worker <devshell_cgal_hole_repair.exe> --prefix <CGAL-prefix> --output-root <local-output>` replays one exact positive fill and four expected refusals. `scientific_cgal_hole_repair_affine.py run` uses the same worker, prefix and output arguments plus `--seed 20261108` to fill four scaled, translated and axis-permuted tetrahedra. Both suites seal source, worker and artifact hashes and support `verify --report`.

`python tools/scientific_cgal_quad_fixture.py verify` checks the authored closed cube and exact two-triangle top removal in a separate CC0 manifest. `scientific_cgal_quad_hole_repair.py run --worker <devshell_cgal_hole_repair.exe> --prefix <CGAL-prefix> --output-root <local-output>` checks one positive square fill and five expected refusals. The independent patch check accepts either diagonal only when two outward triangles retain all original cube faces, cover the four top edges, and restore area 6 and volume 1. `scientific_cgal_quad_hole_affine.py run` uses the same arguments plus `--seed 20261108` for four affine cubes; inverse mapping checks the original square coverage and volume scales cubically. Both reports support `verify --report`. Updating the shared executable changes its hash, so earlier saved triangular-hole reports require a fresh replay before they can verify against the current worker.

`python tools/scientific_cgal_query.py run --worker <devshell_cgal_query.exe> --prefix <CGAL-prefix> --output-root <local-output>` checks five fixed distances and four expected rejections against the authored corpus. `scientific_cgal_query_metamorphic.py run` uses the same arguments plus `--seed <integer>` to check eight affine distance relations. `scientific_cgal_query_oracle.py run --source-report <fixed-or-metamorphic-report.json> --output-root <local-output>` independently computes point-to-triangle distances and verifies each native closest point lies on a triangle. Each suite has `verify --report <saved-report.json>`.

`python tools/scientific_cgal_orientation_fixture.py verify` checks the authored inward-winding tetrahedron. `scientific_cgal_orientation.py run --worker <devshell_cgal_orientation.exe> --prefix <CGAL-prefix> --output-root <local-output>` checks eight fixed inspection, repair and rejection cases. `scientific_cgal_orientation_metamorphic.py run` uses the same arguments plus `--seed <integer>` to reverse four affine tetrahedra, repair them and reopen the outputs. Both runners have `verify --report <saved-report.json>`.

`python tools/scientific_cgal_remesh.py run --worker <devshell_cgal_worker.exe> --prefix <CGAL-prefix> --output-root <local-output>` checks closed tetrahedron and protected square remeshing plus five expected rejections. `scientific_cgal_boundary.py run --remesh-report <remesh-suite.json> --output-root <local-output>` independently checks that every protected square rim edge stays on and covers the original four sides. `scientific_cgal_remesh_metamorphic.py run` uses the same worker/prefix/output arguments and `--seed <integer>` to compare four affine tetrahedron remeshes with a baseline. Reports pin source, executable, fixture and artifact hashes; each runner has `verify --report`.

`scientific_cgal_remesh_reload.py run --remesh-report <remesh-suite.json> --output-root <local-output>` reopens both positive outputs with native validation. `scientific_cgal_remesh_repeat.py run` uses the same arguments and checks three fresh remeshes per fixture against the original output bytes. `scientific_cgal_remesh_open_affine.py run --worker <devshell_cgal_worker.exe> --prefix <CGAL-prefix> --output-root <local-output> --seed 20261108` checks four transformed open squares and inverse-mapped protected rims. `scientific_cgal_remesh_fidelity.py run` uses worker, prefix and output-root to profile six target-edge/iteration settings and independently gates volume drift at 1e-8. On the authored tetrahedron, the 0.5 target with two iterations remains topologically valid but loses about 25% volume, so that setting is ineligible for volume-preserving use. The other five measured settings pass this fixture's volume gate; this is not a global parameter guarantee. Each report supports `verify --report`.

`scientific_cgal_remesh_diagnostics.py run --source-report <fidelity.json> --output-root <local-output>` seals intrinsic triangle angle/shape measurements and bidirectional distances from vertices, edge midpoints and face centroids to the opposite triangulated surface. These finite samples are not a continuous Hausdorff bound. For the authored tetrahedron's 0.5/two-iteration case, vertex distances are effectively zero while facet samples expose maximum deviations of about 0.196 from source to output and 0.125 in reverse. Thus vertex-only checks and minimum triangle angle can miss the geometric change. The diagnostic report also supports `verify --report`.

`scientific_cgal_remesh_acceptance.py run --source-report <diagnostics.json> --output-root <local-output>` applies a fixture-specific volume, sampled-surface and triangle-shape gate; five of six tetrahedron settings are eligible. `scientific_cgal_remesh_profile_reload.py run --source-report <fidelity.json> --output-root <local-output>` natively validates all six outputs, including the low-fidelity mesh. `scientific_cgal_remesh_adverse_affine.py run --worker <devshell_cgal_worker.exe> --prefix <CGAL-prefix> --output-root <local-output> --seed 20261108` replays the 0.5/two-iteration setting on four affine tetrahedra. `scientific_cgal_remesh_failure_reduce.py run --source-report <adverse-affine.json> --output-root <local-output>` removes translation, scale and axis permutation in four recorded steps while preserving the failure. All four reports support `verify --report`. These records do not certify remeshing beyond the named fixture and settings.

`scientific_cgal_remesh_guard.py run --worker <devshell_cgal_worker.exe> --prefix <CGAL-prefix> --input <closed.obj> --target-edge <positive-number> --iterations <1..10> --output-root <local-output>` runs the worker in a fresh directory, retains `candidate.obj` and its sealed measurements, and creates `accepted.obj` only when closed topology, relative volume drift, normalized sampled-surface displacement, minimum angle and shape pass. The local guard requires a bounded outward closed genus-zero triangle input; finite surface samples do not prove a continuous distance bound. `scientific_cgal_remesh_guard_suite.py run --source-report <fidelity.json> --output-root <local-output>` reproduces five accepted and one rejected setting against the sealed native outputs. `scientific_cgal_remesh_guard_affine.py run --source-report <adverse-affine.json> --output-root <local-output>` checks four accepted and four rejected scaled cases. `scientific_cgal_remesh_guard_export.py export --guard-report <accepted-guarded.json> --output-root <local-output>` writes a hash-linked `mesh.obj` and manifest only after verifying an accepted report; rejected reports cannot export. Each guard report has a `verify` command. This is a local laboratory publication path, not a managed or certified broker route.

These are local laboratory checks. The AABB query and orientation repair are not declared as managed desktop capabilities and are absent from the certified Scientific Broker manifest.
