# Scientific typed journey v1

The target demonstration is a nine-stage chain: register two source meshes, validate each, run CGAL Boolean, generate a Gmsh volume and extract its actual boundary, inspect the boundary with VTK, measure with SciPy, import typed geometry and measurement into pulled MATH3D, save/export, then cold-reopen in a new process. `schemas/scientific-typed-journey.v1.json` fixes stage order, operation IDs, and input/output roles. The 3D `gmsh-mesh` remains a separate artifact from the derived 2D `gmsh-boundary`; VTK and SciPy operate on the boundary and cannot claim to inspect volume cells.

The independent `tools/scientific-broker/verify_typed_journey.py --bundle <directory>` checks the `journey.json` manifest and local stage evidence. It requires different source hashes for A and B, closed/manifold/positive-volume topology records for both, exact artifact bytes and SHA-256, source snapshot and consumer commit bindings, explicit length and measurement units, one right-handed coordinate frame, monotonic generation numbers, ordered parent relations, and byte-identical save/export artifacts after a new-process reopen. Paths must remain inside the bundle; symlinks and files larger than 64 MiB are rejected. It returns `verified-artifact-relations-only` deliberately: the verifier cannot itself prove that an algorithm or desktop action ran. Live managed desktop and broker evidence, followed by a trusted signed release bundle, supply that proof.

Each stage has `id`, `state`, `operation`, unique `runId`, ordered `inputs`, ordered `outputs`, and hashed `evidence`. Its evidence JSON binds `runId`, `operation`, `state`, `sourceCommit`, `sourceSnapshotSha256`, `inputHashes`, and `outputHashes`. MATH3D stages additionally bind `consumerCommit`. Each output records `id`, relative `path`, `bytes`, `sha256`, `mediaType`, `frame`, `lengthUnit`, `generation`, `parents`, and `producedBy`. The `scipy` result records a finite surface-area value and tolerance in `m2` or `mm2` matching the declared length unit. The `cold-reopen` result must record `newProcess: true`.

The contract is an acceptance boundary, not a claim that the whole chain is implemented. A completed bundle needs actual typed Gmsh Boolean-surface intake, VTK result transport, SciPy measurement, MATH3D import, and installed desktop evidence before it can pass the release gate.

The candidate `tools/scientific-scipy-surface-measure.py` takes a hash-pinned, bounded VTK VTP artifact and writes `measurement.json` once. It independently decodes the mesh, computes triangle surface area with SciPy's linear algebra norm, compares against scalar reload arithmetic, and records the squared unit, frame, tolerance, source run and snapshot identity. The local VTK-to-SciPy cube smoke measures 24 mm². This candidate still needs managed desktop and broker qualification before it is an available Workbench action.

The candidate `tools/scientific-gmsh-boolean-volume.py` takes a hash-pinned, outward closed manifold Boolean OBJ within 20,000 points and 40,000 triangles. It creates a discrete Gmsh boundary, classifies surfaces, meshes a tetrahedral volume, and records both 2D `InputBoundary` and 3D `BooleanVolume` physical groups. It compares tetrahedral and source signed volumes within 2%, writes `volume.msh` once, and records source run, source snapshot, frame, unit, cell type, dimensions and hashes. The local cube smoke passed a separate MSH reopen with both physical groups and the same tetrahedron count; changed and open inputs were rejected. This remains a candidate: arbitrary Boolean output may be self-intersecting or outside the bounded meshing scope, and no managed Workbench or broker gate exists yet.

The candidate `tools/scientific-gmsh-boundary-extract.py` reloads that MSH, checks both physical group names and dimensions, traverses the actual tetrahedra, and emits their outward closed boundary as a hash-pinned OBJ. A live local segment passed Gmsh volume → extracted boundary → VTK VTP → SciPy surface area on a cube, measuring 24 mm². This proves the format and geometry handoff for that fixture; it does not prove the distinct-input CGAL Boolean or MATH3D product path.
